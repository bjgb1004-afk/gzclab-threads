# 스레드 댓글 자동 답글 설계 (2026-09-25)

## 목적

발행 글 중 "댓글에 구 이름 남겨줘" 형 글에 달린 댓글에, 그 지역의 1등 판매점
TOP3를 자동으로 답글로 단다. 지금은 손으로 일일이 달고 있어서 사실상 방치되고 있다.

답글 자체가 앱이 하는 일의 실물 데모가 되므로, 별도의 홍보 문구 없이도 홍보가 된다.

## 범위

대상: 유도 문구가 "우리 동네도 궁금하면 댓글에 구 이름 남겨줘"인 글 (현재 큐 23건).

대상 아님:
- "여기 가본 집 있음?", "1위 집 앞 지나다닌 사람 있을 텐데 어떤 집인지 앎?" (큐 45건).
  기계가 답할 거리가 없는 잡담 유도다. 고정 문구를 돌리면 같은 댓글창에 비슷한 말이
  스무 개 달려 봇으로 읽힌다.
- 이 두 문구를 지역 요청형으로 바꾸는 것도 지금은 하지 않는다. 잡담글의 성과
  (조회·댓글)가 아직 한 건도 측정되지 않았기 때문이다. `collect_insights.py`가
  `top5-*` / `talk-*`를 구분해 모으고 있으므로 2026-10-15 재점검 때 데이터로 정한다.

## 블로커

현재 `THREADS_TOKEN`에는 답글 읽기 권한이 없다. 확인 결과:

```
GET /{media_id}/replies      -> {"code":10,"message":"Application does not have permission for this action"}
GET /{media_id}/conversation -> 동일
```

답글 쓰기(`threads_content_publish`)는 이미 있다. 필요한 것은
`threads_manage_replies` 한 가지이고, Meta 앱에 권한을 추가한 뒤 인증창을 다시 돌려
단기 토큰 -> 장기 토큰 교환 -> `THREADS_TOKEN` 시크릿 교체가 필요하다(SETUP.md 1단계
재수행). 기존 토큰은 교체 전까지 발행을 계속하므로 서비스 중단은 없다.

## 구조

```
(로컬, 가끔)  districts.json --[bake_replies.py]--> district_replies.json (커밋)
(Actions,10분) queue.json + district_replies.json --[auto_reply.py]--> Threads 답글
```

### 데이터: 답글을 미리 구워서 커밋한다

`districts.json`(277개 구, 369KB)은 lottorich 원본 집계라 공개 저장소에 커밋하지
않는다. 이 판단은 유지한다. 대신 답글 문장을 로컬에서 미리 생성해
`district_replies.json`으로 커밋한다.

```json
{"서울 노원구": "1. 스파 (상계동) — 1등 52회\n2. ...\n\n1위가 2위의 6배임. ..."}
```

- 원본 집계가 아니라 우리가 쓴 문장이므로 재배포 문제가 아니다
- 277개 × 200자 안팎 = 약 55KB (원본의 15%)
- 생성기 `bake_replies.py`는 `gen_district_posts.py`의 `where()`, `name()`, `hook()`을
  그대로 import 한다. 격차 문장 5단계 구간도 같은 함수라 본문과 답글이 어긋나지 않는다
- 새 시도를 추가할 때만 로컬에서 다시 굽고 커밋한다 (지금 `gen_district_posts.py`를
  돌리는 것과 같은 빈도)

### 실행: GitHub Actions cron 10분

`.github/workflows/auto-reply.yml`. 기존 워크플로 3개와 같은 패턴이다.

- PC 전원과 무관하게 GitHub 서버에서 돈다
- 답글까지 5~20분 지연(Actions cron 최소 간격 5분 + 스케줄 지연). 본문에
  "답글 몇 분 걸릴 수 있음"을 적어 기대치를 맞춘다
- 대안이던 로컬 작업 스케줄러(1분, PC 켜져 있어야 함)와 웹훅(즉시, 공개 HTTPS 서버
  필요)은 이 효용에 비해 비용이 크다

### 중복 방지: 상태 파일 없음

`GET /{media_id}/conversation`이 그 글의 모든 답글을 `replied_to`와 함께 한 번에
돌려준다. 내 답글이 달려 있지 않은 댓글만 고르면 되므로, "이미 답한 댓글" 목록을
따로 저장하거나 커밋할 필요가 없다. API 응답이 곧 상태다.

## 답글 규칙

| 댓글 | 판정 | 답글 |
| --- | --- | --- |
| `노원구` / `서울 노원구` / `노원` | 정확히 1곳 매칭 | TOP3 + 격차 한 줄 |
| `중구` / `동구` / `남구` | 여러 시도에 존재 | 되묻기 1회: "중구가 여섯 군데야 ㅋㅋ 서울/부산/대구/인천/대전/울산 중 어디?" |
| `서울` / `경기` | 광역만 | 되묻기: "구까지 말해주면 뽑아줄게" |
| 데이터 없는 지역 | 매칭 실패 | 답하지 않음 |
| `ㅋㅋ`, 딴소리 | 지역명 없음 | 답하지 않음 |

못 알아들었을 때 침묵하는 이유: "무슨 말인지 모르겠어요"가 가장 봇 같고, 그런 댓글은
사람이 직접 답하면 된다. 자동화 대상은 구 이름을 던지는 댓글이고 그게 대부분이다.

답글 형태:

```
chloekim83아 노원구 1등 많이 나온 집 뽑아왔어!

1. 스파 (상계동) — 1등 52회
2. 지원물산 (공릉동) — 8회
3. 노다지복권방 (상계동) — 6회

1위가 2위의 6배임. 이 동네는 사실상 한 집 독주.
```

- 이름은 평문으로 부른다. 멘션(@) 남발은 스팸 신호다
- TOP5가 아니라 TOP3. 답글은 짧아야 읽힌다
- 500자 제한을 넘으면 assert로 굽는 단계에서 잡는다

### 링크를 넣지 않는다

1. 같은 글 댓글창에 동일 Play 링크가 수십 개 달리면 Threads 스팸 판정 대상이다.
   2026-09-25에 계정 플랫폼 차단을 이미 한 번 겪었다
2. 답글 내용 자체가 앱의 실물 데모다. "이 계정은 진짜 이 데이터를 갖고 있다"가
   링크보다 강하다
3. 그 글의 첫 답글에 이미 링크가 달려 있다(`publish.py`). 댓글 단 사람은 이미 봤다

todo.md에서 링크 빈도를 74% -> 39%로 낮춘 판단과 같은 선이다.

## 안전장치

- 하루 상한 50건. 넘으면 중단하고 텔레그램 알림
- 대상은 최근 7일 내 발행글만
- 내 계정(@gzclab) 댓글은 건너뛴다. 안 그러면 자기 링크 답글에 자기가 답한다
- 실패는 기존 방식대로 텔레그램 알림 + 잡을 실패로 끝낸다

## 한도

- GitHub Actions: 이 저장소는 public이라 실행 분 무제한.
  (private이었다면 10분 간격 × 회당 1분 = 144분/일 = 4,320분/월로 무료 2,000분의
  216%, 약 14일이면 소진된다)
- Threads 게시물 생성: 프로필당 24시간 250건. 현재 본문 3 + 링크답글 3 = 6건을 빼면
  자동답글 여유는 하루 244건. 상한 50건은 그 20%다
- Threads 읽기: 10분마다 최근 7일 글(최대 21건) 중 댓글이 있을 수 있는 것만 조회.
  시간당 약 30~120콜로 기본 한도 대비 여유가 있다

## 테스트

네트워크를 타지 않고 `conversation` 응답을 가짜로 넣는다.

- 이미 내 답글이 달린 댓글 -> 건너뜀
- 내 계정 댓글 -> 건너뜀
- 하루 상한 초과 -> 중단 + 알림

## 미결

- 되묻기에 답이 다시 달렸을 때(예: "서울" -> "서울 노원구") 그 답글을 다시 처리하는
  경로. `conversation`은 중첩 답글도 돌려주므로 같은 로직으로 잡히지만, 되묻기가
  무한히 반복되지 않도록 되묻기에는 한 번만 답한다
