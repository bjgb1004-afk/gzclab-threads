# 복권명당 앱 → 스레드 홍보 분석 (2026-10-02)

대상: `ideabox/ruflo-starter` (복권명당, `com.gzc.lottomap`, v1.0.0 / versionCode 2)
관점: 이 계정(@gzclab)이 이미 검증한 포맷 안에서, 앱에 있는데 아직 글로 안 나간 자산을 찾는 것.

---

## 1. 앱 기능 vs 스레드 사용 현황

| 앱 기능 | 코드 근거 | 스레드 사용 |
|---|---|---|
| 구별 1등 TOP5 랭킹 | `app/(tabs)/ranking.tsx` | **쓰는 중** (TOP5 시리즈, 도달 최대 32,012) |
| 천재들의 한수(번호 생성) | `app/(tabs)/more/generator.tsx` | **쓰는 중** (주간 5인 시리즈) |
| **놓친 당첨금(백테스트)** | `app/replay.tsx` | **전혀 안 씀** ← 최대 누락 |
| **QR 스캔 당첨확인 + 보관함** | `app/(tabs)/scan.tsx`, `app/mylotto.tsx` | **전혀 안 씀** |
| 주변 판매점 지도 / 길찾기 | `app/(tabs)/index.tsx`, `app/store/[id].tsx` | 안 씀 |
| 즐겨찾기 · 명당 알림(백그라운드 위치) | `more/favorites.tsx`, `app.config.ts` | 안 씀 |
| 판매점주 등록·관리 | `app/store-owner/{signup,manage}.tsx` | 안 씀 (B2B, 피드 부적합) |

시리즈 2개로 도달은 나오는데, 둘 다 **"정보를 읽고 끝"**이다. 참여 0 문제(`tasks/todo.md`)의
구조적 원인이 여기 있다 — 독자가 할 일이 없다. 아래 2번이 그 반대쪽이다.

---

## 2. 최대 누락: 놓친 당첨금 (`app/replay.tsx`)

앱이 자체 실측해 코드 주석에 박아둔 숫자가 있다. 이건 이 계정에 없던 종류의 소재다.

- 최근 100회 → 평균 **2.5번** 당첨
- 최근 300회 → 평균 **7.2번**
- 전체 회차 → 평균 **23.1번**
- 982회 기준 평균 23번, **최소도 12번** (누가 열어도 결과가 비지 않음)
- 200세트 중 100회 구간 무당첨은 **13세트뿐**

왜 스레드에 맞나:

1. **독자가 자기 번호를 갖고 있다.** TOP5는 "우리 동네 알려줘"지만 이건 "내 번호 돌려줘"다.
   이미 검증된 댓글 유도(구 이름)와 같은 구조인데, 입력값이 더 개인적이다.
2. **숫자가 반박 불가능하다.** "23번 당첨돼 있다"는 사실 진술이고, 인과("그러니 또 나온다")를
   안 써도 성립한다 — 계정이 지키고 있는 원칙과 충돌하지 않는다.
3. **앱을 열 이유가 그 자리에서 생긴다.** 랭킹 글은 읽고 나면 끝이지만, 자기 번호 결과는
   앱에서만 볼 수 있다.

## 4. 바로 큐에 넣을 글 4편

같은 폴더 `new_posts.json`에 queue.json 포맷으로 들어 있다. 붙이는 법:

```bash
python - <<'EOF'
import json, pathlib
q = pathlib.Path("queue.json"); new = pathlib.Path("docs/new_posts.json")
queue = json.loads(q.read_text(encoding="utf-8"))
have = {p["id"] for p in queue}
add = [p for p in json.loads(new.read_text(encoding="utf-8")) if p["id"] not in have]
q.write_text(json.dumps(add + queue, ensure_ascii=False, indent=2) + "\n", encoding="utf-8")
print(f"{len(add)}개 추가")
EOF
```

| id | 슬롯 | 글자수 | 링크 | 소재 |
|---|---|---|---|---|
| `replay-1` | pm | 254 | o (`?c=replay`) | 전 회차 평균 23.1번 당첨 |
| `replay-2` | night | 222 | x | 같은 번호만 산 사람 / 5등 미교환 |
| `genius-same-1` | pm | 247 | x | 스레드 번호 = 앱 번호, 비트 단위 동일 |
| `qr-scan-1` | night | 209 | o (`?c=scan`) | QR 당첨확인 + 보관함, 지급기한 1년 |

지킨 규칙 (`SETUP.md`, `gen_district_posts.py`, `tasks/todo.md` 기준):

- 500자 한도 — 최대 254자
- **둘째 줄이 팔로우 유도** (팔로워 235명 중 200명이 이 위치의 문구에서 온 글 하나로 들어왔음)
- 링크는 본문이 아니라 `link` 필드 → `publish.py`가 첫 댓글로 붙임
- 링크는 랜딩(`gzclab.com/lottomap/?c=`) 경유 — Play 직링은 og:image가 구글 기본 아이콘으로 뜸
- **링크 빈도 50%(4건 중 2건)** — 39% 기준에 맞춤. genius 글은 번호 시리즈에 매일 링크 답글이
  이미 붙으므로 링크 제거
- 반말·`~함` 종결, 인과 주장 없음, 사실만

## 5. 운영 주의 — 이 4편은 자동답글 대상이 아니다

`auto_reply.targets()`는 본문에 **"구 이름 남겨줘"**가 든 글만 고른다. 위 4편은 지역을 묻지
않으니 그 문구가 없고, 따라서 댓글이 와도 자동답글이 **안 나간다.**

`replay-1`·`replay-2`는 "자기 번호 댓글에 남겨봐"로 댓글을 유도하므로, 둘 중 하나:

- **(a) 수동 답글.** 하루 몇 건이면 직접 답하는 게 낫다. 시작은 이쪽을 권한다 — 반응 규모를
  모르는 상태에서 코드를 먼저 쓰면 헛일이 된다.
- **(b) `auto_reply.py` 확장.** 댓글에서 숫자 6개를 파싱해 `replay` 로직을 돌려 답글.
  이미 `src/features/backtest/replay.ts`에 로직이 있어 파이썬 포팅만 필요하고,
  `lotto_gen.py`↔`geniusGenerator.ts`처럼 **양쪽 GOLDEN 테스트를 맞춰야 한다.**
  반응이 붙은 뒤에 결정한다.

`qr-scan-1`·`genius-same-1`은 댓글을 직접 요구하지 않으니 그대로 둬도 된다.

## 6. 홍보에서 쓰면 안 되는 표현

스토어 심사·법적 리스크. `docs/play-store-listing.md`가 콘텐츠 등급 설문을 "도박 아님"으로
답하는 근거와 직결되므로, 스레드 글도 같은 선을 지켜야 한다.

- ❌ "여기서 사면 나온다", "확률 높은 집" → 당첨 확률 보장·암시. 스토어 설명에 명시한
  "향후 당첨 확률을 보장하지 않습니다"와 정면으로 어긋난다.
- ❌ "예측", "적중률" → 번호 생성기를 예측 도구로 포장하는 순간 성격이 바뀐다.
  현재 `lotto_picks.py`가 쓰는 "채점"이 맞는 단어다.
- ❌ 앱에서 복권을 살 수 있다는 오해를 줄 표현 → 구매·중개 기능 없음.
- ⚠️ "공공데이터 기반"을 단독으로 쓰지 말 것. 판매점 위치는 공공데이터포털이지만
  **1·2등 배출 집계는 아니다** — `README.md`가 `fetchPrizeStoreAnnouncements()`를
  자리표시자(stub)로 적어뒀고, 실제 구별 집계는 `districts.json`(lottorich 원본, 비공개·미커밋)에서
  온다. 글에는 출처를 특정하지 말고 "지금까지 1등 나온 횟수" 같은 사실 진술만 쓴다.

데이터 품질 리스크 하나 더: `store-name-candidates.txt` 기준 306곳 중 **70곳(23%)만** 간판명
후보가 잡혔고, 나머지는 상호가 `복권방`·`로또`·`상호없음`이다. TOP5 1위 칸에 "복권방"이
찍히면 글의 신뢰가 깎인다 — 후보 반영을 TOP5 발행보다 먼저 돌리는 게 낫다.

## 7. 측정

`collect_insights.py`가 발행 24시간 뒤 1회만 수집한다. 이 4편은 `?c=` 값이 달라서
Play Console 유입 리포트에서 캠페인별로 갈린다.

| 보는 값 | 어디서 | 판단 |
|---|---|---|
| 도달 | `queue.json`의 `insights` | TOP5 중앙값(2,676) 대비 |
| **외부 댓글 수** | 같은 곳 `replies` − 내가 단 답글 | 지금 0. 이게 이 4편의 실제 목적 |
| 설치 기여 | Play Console → 유입 경로 `?c=replay` / `?c=scan` | 어느 소재가 설치로 가는지 |

2주 뒤 판단 기준: `replay-*`의 외부 댓글이 TOP5보다 많으면 백테스트 축을 시리즈로 늘린다
(구간별·번호별로 글감이 무한하다). 도달만 나오고 댓글이 또 0이면 원인은 소재가 아니라
포맷이므로 TOP5와 같은 진단을 다시 해야 한다.
